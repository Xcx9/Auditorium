# Переход со старой модели данных

Документ фиксирует соответствие моделей и политику сохранения данных на 24 ноября 2026 года. Порядок резервирования, применения и восстановления приведён в [инструкции работы с базой](../database-migration.md). Модель и API описаны в [контрактах backend](backend-contracts.md).

## Соответствие моделей

| Источник или прежнее представление | Рабочая модель | Политика |
| --- | --- | --- |
| Audiences с Id и Name | Room с Id, Number и SourceScheduleCode | Существующие Id и названия перенесены. Код МИЭТ хранится отдельно и позволяет менять название без потери связей |
| Старые Lessons с учебной неделей и временем суток | LegacyLessons и новые Lesson в ScheduleEntries | Исходные строки сохраняются архивом. Рабочие календарные занятия создаются из датированного импорта |
| Класс ScheduleEntry | Класс Lesson | Имя таблицы ScheduleEntries сохранено для рабочей модели. Исторические имена миграций сохраняются |
| Сохранённый Room.Status/State | Room.Status(date, isOccupied) | Колонка статуса удалена AlignScheduleStorage. Значение вычисляется из расписания и активной отметки при покрытой дате |
| Отметка с флагом IsCancelled | OccupancyMark с ClosedAt | Политика зависит от наличия исходного времени закрытия. В найденных локальных базах перенос таких записей неприменим |
| Копия расписания в памяти | ScheduleSnapshot, Rooms.ScheduleDates и ScheduleImportState | Хранятся занятия, покрытые даты, время последнего успеха и признак сбоя |

Room.Building вычисляется из номера и не отображается в колонку EF. Новый формат принимает цифровой номер с допустимым суффиксом длиной до 20 символов. Старые именованные записи, перенесённые миграциями, сохраняются. Импорт новых расписаний ограничен цифровыми аудиториями 3-го и 4-го корпусов.

## Даты старого расписания

В проверенном исходном расписании TimeFrom/TimeTo имели дату 0001-01-01, а Semester был пуст. Эти поля подтверждают часы занятия, но не календарную дату. При переходе такие строки остаются в LegacyLessons. Рабочие занятия и ScheduleDates заполняются при новом импорте с заданным семестром и периодом из учебного календаря.

Покрытый день без пар записывается в ScheduleDates. Пустой список покрытия означает отсутствие подтверждённых дат. После перезапуска последняя копия и метаданные читаются через ScheduleSnapshotStore.

## История отметок

Рабочая отметка активна при ClosedAt == null. Закрытие сохраняет исходную запись. Частичные уникальные индексы защищают только активные UserId и RoomId. AutoReleaseAt задаёт ближайшее начало занятия после CreatedAt, при отсутствии такого занятия остаётся null.

Инвентаризация 23 ноября 2026 года дала следующие результаты.

| Найденная база | Отметки и формат |
| --- | --- |
| Рабочая auditorium.db | OccupancyMarks пуста, используется ClosedAt |
| Копия перед обновлением от 08.11.2026 | OccupancyMarks пуста, используется ClosedAt |
| Копия до перехода на UTC от 27.10.2026 | Таблицы отметок и пользователей отсутствуют |
| База из локального Auditorium.zip | Только старые Audiences/Lessons, отметок нет |

Старую базу с IsCancelled и историей отметок локально не нашли. Реализация переноса неизвестного времени отмены для такого формата не требуется найденным данным и не заявляется поддержанной.

Если появится другой исходный формат с IsCancelled == true и неизвестной датой отмены, его сначала следует исследовать отдельно. Прямое преобразование в ClosedAt == null восстановило бы активность. Подстановка даты создала бы недостоверную историю. Конкретная схема переноса должна сохранить факт отмены, исходные идентификаторы и связи без выдуманного времени. Скрипт текущего проекта этот вариант не преобразует.

## Хранение времени и история миграций

DateTimeOffset рабочих занятий и отметок конвертируется в UTC ticks типа INTEGER. Нормализуется смещение, сохраняется момент времени. Московская дата определяется через IClock и Europe/Moscow. Дата начала старого семестра автоматически не выдумывается.

Цепочка миграций сохраняет InitialCreate, AddSemester, AddAudiencesTable, PreserveLegacyScheduleAndUseUtcTime, AlignScheduleStorage, MapRoomsByScheduleCode и AddAuthenticationStorage. Последняя добавляет сравнение логинов NOCASE после проверки конфликтов и согласована с текущей моделью EF.

Архивные таблицы сохраняются вне текущей EF-модели. Down миграции перехода на UTC запрещён в реализации, поскольку удаление новых таблиц уничтожило бы созданные после перехода данные. Восстановление выполняется из резервной копии с учётом новых записей.

Постоянные ScheduleMigrationTests и AccountMigrationTests проверяют пустую базу, переход старой схемы, сохранение строк/связей и повторное применение. Общий набор Core/Infrastructure содержит 58 тестов. Проверка применения к конкретной рабочей базе требует отдельной резервной копии этой базы.
