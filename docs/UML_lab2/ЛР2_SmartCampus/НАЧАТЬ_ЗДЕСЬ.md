Версия комплекта: 1.0. Основание — принятое ТЗ `SmartCampus_LR1_доработанный .docx`.

## Что открыть сначала

1. `SmartCampus_ЛР2_отчет.pdf` — отчет, объяснения и все 15 диаграмм. Большие схемы находятся на увеличенных листах для показа на экране.

3. `SmartCampus.code-workspace` — открыть через VS Code. Или выбрать **Файл → Открыть папку → ЛР2_SmartCampus**.

## Состав схем

**Сначала открыть `00_usecase_complete`: главная диаграмма со всеми 13 функциями пункта 5.1.1 ТЗ на одном листе.** Далее идут уточняющие схемы:

1. `01_usecase_user` — возможности пользователя.

3. `03_class_domain` — предметные классы; Status находится в Room.

5. `05_activity_user` — полный путь пользователя.
6. `06_activity_create` — создание и проверки.
7. `07_activity_sync` — обновление расписания.
8. `08_sequence_auth` — регистрация и вход.
9. `09_sequence_search` — поиск и карточка.
10. `10_sequence_create` — создание и конкурентный конфликт.
11. `11_sequence_cancel` — просмотр и снятие своей отметки.
12. `12_sequence_auto` — автоматическое снятие.
13. `13_sequence_sync` — получение расписания и резервная копия.
14. `14_example_person` — отдельный пример методички.

## Генерация и запуск

В VS Code выберите **Терминал → Выполнить задачу → ЛР2: запустить демонстрации**.

Или в PowerShell из этой папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Run-Demo.ps1
```

Этот запуск заново генерирует C# из диаграмм, собирает и выполняет два проекта. Нужен .NET SDK 10, который уже установлен на данном компьютере. Внешние NuGet-пакеты не требуются. `ExecutionPolicy Bypass` действует только на запущенный процесс и не меняет системную настройку.

Ожидаемые финальные сообщения:

```text
RESULT: 22 checks passed
PASS: refactoring preserves results for 3 input sets
```

Фактический вывод выполненной проверки находится в `evidence/demo-log.txt`.

## Как устроен код — простыми словами

`app/Generated/Domain.g.cs` — автоматически полученные «карточки данных». `Room` похож на карточку помещения: номер, корпус, текущий статус. `OccupancyMark` — запись о том, кто пользуется этим помещением. Отдельная запись нужна для проверки автора; отдельный класс статуса не нужен.

`app/CampusService.cs` — правила работы с карточками. `FindFree` выбирает свободные аудитории с известным расписанием. `CreateMark` сначала проверяет ограничения и только затем добавляет запись. `CancelMark` проверяет автора и закрывает запись. `ReleaseDueMarks` закрывает отметки при начале следующего занятия.

`lock` похож на один ключ от журнала: пока один запрос проверяет и записывает данные, второй ждет. Это учебная защита внутри одного процесса. В будущем веб-приложении требуется транзакция БД и уникальные ограничения.

`app/Program.cs` — сценарий демонстрации. Он подготавливает данные, выполняет действия и проверяет результат. Это три шага: «дано → сделали → проверили». Часы управляемые, чтобы не ждать настоящего начала занятия. Пользователь будущего сайта время отметки выбирать не будет.

`tools/Generate-Code.ps1` — читает именно `.puml`, находит классы и свойства и записывает C#. Поддерживает только синтаксис, использованный в этих двух диаграммах. После изменения исходной диаграммы генерацию можно повторить; сгенерированные файлы будут перезаписаны.

`example/Generated/Person.g.cs` — сгенерированные заглушки. `example/Person.cs` — доработанный пример. `example/PersonBefore.cs` — версия до выделения метода Initial. `example/Program.cs` — запуск и сравнение результатов до и после рефакторинга.

## Важные ответы на защите

- У Use-case функции — **овалы**, граница системы — прямоугольник.
- В активности условие — **ромб**, действие — скругленный прямоугольник.
- В последовательности время идет **сверху вниз**; слева направо стоят участники. Условия обозначаются рамками `alt`, а не ромбами.
- «Нет активной отметки» проверяется при **создании**, а при **снятии** нужна существующая своя отметка.
- После автоматического снятия аудитория может быть **занята официальным занятием**.
- **60 минут — интервал обновления расписания**, а не срок действия отметки.
- Нет следующего занятия — нет автоматического снятия по произвольному таймеру.
- Нет данных на текущую дату — аудиторию не показываем свободной; свою отметку снять можно.

## Граница выполненного

Диаграммы проектируют все обязательные функции актуального ТЗ. Исполняемый пример ЛР2 проверяет ядро на контрольных данных в памяти. Здесь нет готового веб-интерфейса, реальной авторизации, подключения парсера к МИЭТ и постоянной БД. Нагрузочные и приемочные испытания полного продукта не выполнены.

В методичке фактически указана **Visual Studio 2013**. Использование VS Code/PlantUML — адаптация инструментов по вашему запросу, а не воспроизведение Modeling Project. Требование старого интерфейса среды может отдельно оцениваться преподавателем.

Исходное ТЗ и файл пробника сохранены без изменений. GitHub-публикации не выполнялись.
