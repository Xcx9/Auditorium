# Переход базы Auditorium на модель с временем UTC

Миграция `20261027191206_PreserveLegacyScheduleAndUseUtcTime` архивирует старое
расписание и создаёт рабочие таблицы. Следующая миграция, `AlignScheduleStorage`,
удаляет колонку `Rooms.Status` и добавляет таблицу `ScheduleImportState` для
времени последнего успешного обновления и признака сбоя.

## Сохранённые данные

- `Audiences` переименована в `LegacyAudiences` без изменения столбцов и строк.
- `Lessons` переименована в `LegacyLessons` без изменения столбцов и строк.
- В `Rooms` перенесены все идентификаторы и названия из `LegacyAudiences`.
- Созданы `Users`, `ScheduleEntries`, `OccupancyMarks` с внешними ключами.
- В `Rooms.ScheduleDates` хранится JSON-массив подтверждённых календарных дат.
- Временные поля рабочих занятий и отметок хранят UTC ticks (`INTEGER`) и
  читаются EF Core как `DateTimeOffset` с нулевым смещением. Для отображения
  и календарной даты используется `IClock` с часовым поясом Europe/Moscow.
- Уникальные индексы отметок действуют только при `ClosedAt IS NULL`, поэтому
  история закрытий не мешает создавать новые отметки.

Архивные таблицы намеренно не входят в текущую EF-модель. Не удаляйте их:
это полный первоисточник старого расписания, включая преподавателей, группы,
недели и время занятий. Изменение времени старых миграций не требуется.

## Почему новые занятия не заполняются автоматически

В проверенной старой базе все 24 340 строк содержали `TimeFrom`/`TimeTo`
с датой `0001-01-01`, а `Semester` не был заполнен. Эти значения определяют
часы и минуты занятия, но не его реальную календарную дату. Без начала
семестра и подтверждённой привязки учебных недель нельзя получить достоверные
`StartsAt`/`EndsAt`.

Поэтому после переноса `ScheduleEntries` пуст, а `Rooms.ScheduleDates` содержит
пустые списки. Сервис исключает такие аудитории из поиска свободных и запрещает
создание отметки с кодом `ScheduleNotCovered`. Ручное снятие существующей отметки
не требует покрытия расписания. Для активации расписания нужно загрузить
датированные занятия или выполнить отдельный импорт из архива с проверенным
календарём семестра. Дни с подтверждённым отсутствием занятий тоже должны быть
добавлены в `ScheduleDates`.

## Применение к другой старой базе

Остановите запись в базу на время обслуживания и выполните из корня репозитория:

```bash
dotnet build Auditorium.slnx
python3 scripts/migrate_database.py --database Auditorium.Web/auditorium.db
```

Инструмент использует SQLite Backup API, сохраняет резервную копию в
`Auditorium.Web/backups`, применяет миграцию сначала на временной копии,
сравнивает число и SHA-256 содержимого всех исходных строк, проверяет
целостность и внешние ключи. Он также проверяет повторное применение,
после чего обновляет исходную базу и записывает JSON-отчёт рядом с копией.
Повторный запуск для уже обновлённой базы ничего не меняет.

Скрипт поддерживает исходную базу и базу, к которой уже применён переход на UTC.
Во втором случае сверяются также записи пользователей, занятий, отметок и
покрытие аудиторий. Для новой пустой базы выполните

```bash
dotnet ef database update --project Auditorium.Infrastructure --connection 'Data Source=/path/to/auditorium.db'
```

## Загрузка расписания

`IScheduleParser.LoadAndValidate` принимает название семестра и включительный
период до 28 дней из подтверждённого учебного календаря. Парсер получает каталог и
ответ по аудиториям 3-го и 4-го корпусов с публичной страницы МИЭТ. Корпус
определяется по первой цифре номера аудитории. Даты вычисляются по
опубликованному на странице началу четырёхнедельного цикла, время интерпретируется
в Europe/Moscow. Пропуски и исключения в календаре должны учитываться при выборе
периода: сам ответ источника содержит повторяющееся недельное расписание.

Парсер возвращает кандидата с кодами аудиторий источника, покрытыми датами и
занятиями либо ошибку всего запроса. Для перенесённых аудиторий миграция
`MapRoomsByScheduleCode` переносит код из `LegacyAudiences.Id` в уникальную
колонку `Rooms.SourceScheduleCode`. Номер используется для отображения, а
внутренний ID аудитории остаётся прежним при переименовании.

После применения миграций можно выполнить разовое обновление. Подставьте
название семестра и включительные даты из подтверждённого учебного календаря.
Целевую базу можно указать через `ConnectionStrings__DefaultConnection`.

```bash
dotnet run --project Auditorium.Web -- refresh-schedule "Осенний семестр 2026/2027" 2026-11-07 2026-11-09
```

Успешное обновление заменяет рабочую копию расписания и покрытие дат, а также
сохраняет время обновления в `ScheduleImportState`. Аудитории, которых нет в
новом каталоге, остаются в базе со своей историей отметок и пустым покрытием.
При сбое прежняя копия остаётся доступной, а в метаданных фиксируется ошибка.

## Восстановление

Автоматический `Down` миграции перехода на UTC запрещён: удаление новых таблиц могло бы уничтожить
пользователей и отметки, созданные после перехода. При необходимости
восстановления остановите приложение и сохраните также текущую базу через
SQLite Backup API. Восстанавливайте нужную резервную копию через этот же API;
не подменяйте открытый файл SQLite вместе с оставшимися WAL/SHM-файлами.
Если после перехода появились новые данные, их перенос требует отдельного плана.
