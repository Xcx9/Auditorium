# Auditorium

Auditorium помогает найти свободную аудиторию в МИЭТ. Система объединяет официальное расписание и пользовательские отметки о занятости.

## Состояние на 24 ноября 2026 года

Backend Core/Infrastructure опубликован в feature/core-logic коммитом f737b915f9d2e7b2fb93173c28803bedcdbe781e. Документационный выпуск переносит проверенную реализацию в dev. Включение изменений в main определяется историей слияний.

Реализованы каталог, поиск по корпусу и части номера, карточка, просмотр своей отметки, создание/снятие и обработка наступившего автоснятия. Имеются Core-регистрация и проверка пароля, парсер МИЭТ, постоянная копия расписания, метаданные обновления и миграции SQLite.

Web пока содержит стартовые страницы ASP.NET Core и разовую команду импорта. Экраны поиска/карточки/отметки, HTTP-вход, cookies/claims, CSRF и фоновые обработчики ведутся в [плане Web #49](https://github.com/Xcx9/Auditorium/issues/49).

## Правила работы

Занятость определяется текущим занятием или активной отметкой. Занятие действует в интервале StartsAt <= now < EndsAt. У пользователя и аудитории может быть по одной активной отметке. Закрытие сохраняет историю.

На дату без подтверждённого расписания карточка сохраняется без статуса, создание отметки запрещено. Общий каталог возвращает все записи из базы. Поиск свободных показывает аудитории с покрытием и отдельно сообщает число совпадений без расписания. Сбой обновления сохраняет предыдущую копию и её метаданные.

Новые аудитории имеют четыре цифры с допустимыми буквенными дополнениями, например 3102а или 3120 а (к). Корпус определяется первой цифрой. Парсер импортирует расписание 3-го и 4-го корпусов за явно заданный период. Срок автоснятия — начало следующей пары, либо null при её отсутствии.

## Подготовка и запуск

Нужен .NET SDK 10. Из корня репозитория выполните

```bash
dotnet restore Auditorium.slnx
dotnet build Auditorium.slnx
dotnet test Auditorium.slnx --no-build
```

Полный набор Core/Infrastructure прошёл 23 ноября 2026 года — 58 тестов, 0 ошибок и 0 пропусков. Проверяются домен, конкуренция независимых соединений SQLite, парсер, сохранение копии, миграции и авторизация. Браузерные проверки относятся к Web.

Новую или существующую базу подготовьте по [инструкции миграции](docs/database-migration.md). Затем запустите

```bash
dotnet run --project Auditorium.Web/Auditorium.Web.csproj
```

Адрес отображается в консоли. Соединение SQLite задаётся ConnectionStrings:DefaultConnection в [appsettings.json](Auditorium.Web/appsettings.json) или переменной ConnectionStrings__DefaultConnection. Текущий Web открывает стартовую страницу. Команда refresh-schedule и требования к учебному календарю описаны в инструкции базы.

## Структура

| Проект | Ответственность |
| --- | --- |
| [Core](Auditorium.Core/) | Сущности, правила, сервисы и интерфейсы |
| [Infrastructure](Auditorium.Infrastructure/) | EF Core/SQLite, парсер МИЭТ, часы и хэширование |
| [Web](Auditorium.Web/) | HTTP, Razor, сессия, DI и фоновые адаптеры |
| [Tests](Auditorium.Tests/) | Постоянные проверки Core/Infrastructure |

Infrastructure зависит от Core. Core не содержит зависимости от EF Core. Учебные app/ и example/ из комплекта ЛР2 находятся вне Auditorium.slnx.
